## Root causes and fixes

**#116 was three clamping gaps, not the column split.** Family-feed's tall
variant sliced a fixed three posts under `overflow-hidden`; `useFitRows` trusted
rects measured while a container-query variant was `display: none`, so after a
breakpoint crossing the clamp never engaged (all-zero bottoms → show
everything); and meals painted an empty NEXT UP groove stating "+3 more days"
when zero rows fit. Feed now uses `useFitRows`; the hook re-measures when a
hidden-at-mount box is revealed (new test); the meals groove blanks its visuals
when empty — visuals only, layout untouched, or the measured box resizes and the
clamp oscillates.

**Geometry gates.** #116 first gated to equal thirds; live review reversed it —
meals stays **2×2** because the h=2 slot floors at 376px, the only geometry that
guarantees ≥1 lookahead row at every viewport (an h=1 tile lands wherever the
grid deals it, incl. heights where the large variant fits no row). Standing rule
confirmed: `MIN_ROW_HEIGHT` 180 means an h=1 slot can be 180–400px — a widget
must survive that whole range. #117 gated to **stacked day headers**: below
`WIDGET_CQ.narrowMaxWidth` (439px) the calendar day list gives each day its own
header line ("Tomorrow · Aug 21") and event rows the full width, avatars kept;
the header lives inside its day's first row element so the clamp can't strand
it. #118 gated to Teddy's grid with one amendment: chores leads the right
column, not meals — the elevation invariant (no quiet above a card) and the kid
ranking both demand it. Applied to tiers 1–3 (teens keep no feature).

**The prod-blocking find: seeded `default_layout_*` config rows.** The seed
upserted `DEFAULT_LAYOUTS` into `system_config` and `/home/layout` serves config
over code — so prod, where the seed never runs, would have kept deploy-zero
geometry forever. Seed and `/dev/reset` no longer write those keys; migration
`20260820230000_unseed_default_layouts` deletes the three rows (verified
identical to the old in-code default first); the config key remains as a
deliberate per-deploy override, tested in `home.test.ts`.
