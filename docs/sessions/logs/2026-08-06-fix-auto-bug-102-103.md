## Root cause

**#102** — `reconcileRoutines` (auto-bug #92's fix) re-dates a fallen-behind
open row to the next occurrence rather than spawning a new one — "this week's
trash, not last week's debt." That roll only touched `dueDate`. For a
fixed-assignee routine that's a no-op; for an **up-for-grabs** routine
(`routine.assigneeId === null`) whose task had been claimed but never
completed, the claim rode along on every subsequent roll, so the chore never
came back up for grabs — it just quietly became that kid's forever.

**#103** — The Wallets tab's punch-card row rendered two `flex-none` text
buttons ("Undo last punch", "Take it down") beside the title. `flex-none`
never yields space, so on a phone-width viewport the `min-w-0 flex-1` title
column got squeezed to a sliver to make room for two `whitespace-nowrap`
buttons that together needed most of the row.

## Fix (PR #104, merged `2d7aad5`)

**#102** — the roll now re-stamps `assigneeId: routine.assigneeId` alongside
`dueDate`. Matches the schema's own stated contract ("a routine stamps these
fields onto each occurrence it materializes") — a no-op for fixed-assignee
routines, a release back to up-for-grabs otherwise. New repro test: claim an
up-for-grabs days-routine occurrence, let it roll to the next scheduled day
without completing it, assert `assigneeId` is null again.

**#103** — first pass wrapped the row and let the buttons drop to their own
line below `sm`; live-reviewed and it read as orphaned whitespace (buttons
floating far right under a mostly-empty row). Gated three options with the
user (icon buttons · stacked text left-aligned · icon+destructive-text
hybrid) — **icon buttons** won: swapped both for the `RowActions` recipe
already used elsewhere (44px ghost buttons, `RotateCcw` / `Trash2`,
`aria-label` + `title` carrying the words), which never needs to wrap at any
width.

75 tests green in `chores.test.ts` + `chore-routines.test.ts`. Both fixes
live-reviewed on dev with Zach before close-out.
