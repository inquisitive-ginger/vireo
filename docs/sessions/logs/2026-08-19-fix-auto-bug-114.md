## Root cause and fix

`is_activity` was derived as `weekly && attendeeIds.length === 1` (ADR 038) —
a shared standing commitment fell through. Widened to `>= 1` (Family/zero-attendee
events still excluded) and **amended ADR 038 in place** (its "do not revisit
unless" guards the storage model, not this derivation). Migration
`20260819120000_shared_activities` backfills existing rows — Dad's report is
about an already-created event, so the write-path change alone would not have
fixed it.

Roster presentation gated and approved: **row under each kid** (vs a separate
"Shared" group) — a shared activity fans into every attendee's group so each
kid's weekday-load strip stays truthful, with the co-attendee named in the row
meta ("… · with Teddy", ADR 044 second channel). Seasons dedupes to one bar per
series: a hue dot per attendee, `fillForHues` split-tint fill. The roster no
longer keys off the serialized `ownerId` (null for shared) — it fans out over
`attendeeIds`.
